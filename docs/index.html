FedoraWin DE implements the current GNOME desktop interaction model on Windows. FedoraWin Shell provides the panel, Activities, app grid, workspaces, calendar, Quick Settings and desktop presentation while Windows remains the underlying API and compositor platform. The always-on top panel is native Rust/Win32, richer shell surfaces load on demand, and real application windows keep Windows-owned caption buttons, Snap, resize and hit testing.

CURRENT 0.4.0-DEV · GNOME 51

What is actually working now.

The site tracks the current native development branch and keeps implemented behavior separate from planned shell work.

◉

Live Activities overview

Activities tracks real Windows lifecycle events and renders live application content through DWM thumbnails. Window activation and close actions operate on the real HWNDs, and the overview no longer exposes a persistent loading placeholder.

▰

Native GNOME panel

The always-resident top panel is a lightweight Rust/Win32 surface. Activities, clock and system areas remain GNOME interaction entry points while rich surfaces stay lazy.

◫

Real libadwaita on Win32

A separate FedoraWin-owned GTK4/libadwaita executable now compiles and runs on Windows with actual AdwApplicationWindow, AdwToolbarView and AdwHeaderBar widgets. Dark and light HWND captures passed Windows CI. It is still an isolated proof, not the production shell or a global theme for Windows applications.

Inspect real dark/light captures →

↔

Real workspace navigation

FedoraWin reads Windows virtual-desktop IDs and Activities previous/next controls switch the actual Windows desktop. FedoraWin-initiated moves remain journaled for undo.

▦

GNOME 51 app grid

The 24-app page uses a GNOME-like 6×4 layout with roomier app tiles, dash proportions, page indicators, keyboard focus treatment and reduced-motion support.

⌁

Quick Settings + control flyouts

Appearance, Wi-Fi, master volume, battery, screenshot, Power Mode, internal-display brightness and Bluetooth now have native-backed paths. Wi-Fi reports the real radio state, current SSID and adapter in a GNOME-style detail flyout; Power Mode, Wi-Fi and Bluetooth share one reusable GNOME control-flyout manager, while brightness reads and writes the laptop panel through the Windows monitor WMI provider. Wireless Pause now coordinates supported Wi-Fi and Bluetooth radios, confirms each result and restores their previous states during the same session. Windows system-wide Airplane Mode remains outside its scope.

ARCHITECTURE

Native when always-on. Web when rich.

The panel is native Rust/Win32 to keep idle memory tiny. Tauri/WebView2 is reserved for richer GNOME surfaces that are created on demand and destroyed when dismissed.

WHY NOT BETA YET?

FedoraWin DE is becoming behavioral, not decorative.

Native DWM window integration, AppBar work-area reservation, live overview windows, WinEvent lifecycle tracking, workspace identity, native Power Mode and the lightweight panel are already in the core. Remaining major gaps include integrating the tested real libadwaita window into FedoraWin-owned production surfaces, measuring the full GTK process-tree budget, advancing an optional frame engine (same-process attach/rollback verified; third-party injection unimplemented), dynamic workspace semantics, safe bare-Super handling, gestures and wider physical hardware testing.

0.4 DEVCurrent native branch is gated by Windows build, runtime capture and memory checks.
Beta starts only after the remaining behavior and hardware-stability gates are complete.
