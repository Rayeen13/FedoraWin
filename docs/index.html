CURRENT 0.4.0-DEV

What is actually working now.

The site distinguishes implemented behavior from scaffolding so screenshots and status never outrun the code.

◉

Live Activities overview

Activities tracks real Windows lifecycle events and renders live application content through DWM thumbnails. Window activation and close actions operate on the real HWNDs.

▰

Native GNOME panel

The always-resident top panel is now a lightweight Rust/Win32 surface rather than a permanent WebView. Activities, clock and system areas remain GNOME interaction entry points.

◫

Adwaita window chrome

Real HWNDs keep Windows resize/Snap mechanics and Windows-owned caption buttons while FedoraWin applies reversible Adwaita-inspired DWM colors, text colors, borders and rounded-corner preferences.

↔

Real workspace navigation

FedoraWin reads real Windows virtual-desktop IDs and Activities now has previous/next controls that switch the actual Windows desktop. FedoraWin-initiated window moves remain journaled for undo.

⌁

Quick Settings

Appearance, Wi-Fi, master volume and battery status have native-backed behavior today. Brightness, Bluetooth, airplane and power controls remain staged for direct Windows APIs.

⌨

Activities keyboard entry

Alt+F1 is globally registered with Win32 and toggles Activities. Bare Super is intentionally not claimed until Win-key shortcuts can be preserved safely.

ARCHITECTURE

Native when always-on. Web when rich.

The panel is now native Rust/Win32 to keep idle memory tiny. Tauri/WebView2 is reserved for richer GNOME surfaces that are created on demand and destroyed when dismissed.

WHY NOT BETA YET?

The shell is becoming behavioral, not decorative.

Live DWM overview windows, WinEvent lifecycle tracking, real workspace identity and the native lightweight panel are now in the core. Remaining major gaps include full workspace navigation semantics, safe bare-Super handling, more direct Quick Settings APIs, touchpad gestures and broader multi-monitor testing.
