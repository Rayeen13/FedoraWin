CURRENT 0.4.0-DEV

What is actually working now.

The site distinguishes implemented behavior from scaffolding so screenshots and status never outrun the code.

◉

Activities shell

Activities opens as a native Tauri shell surface, lists real top-level windows, activates them and hosts app search plus the dash.

▦

Apps + GNOME aliases

Installed applications come from Windows and aliases map GNOME-style searches such as Terminal, Files and System Monitor to Windows equivalents.

◫

Adwaita + native DWM frames

The shell now follows current libadwaita color roles, circular toolbar controls and GNOME motion. Real HWNDs receive matching rounded DWM frames while Windows keeps caption-button hit-testing and Snap behavior.

↔

Display topology

Monitor enumeration tracks physical bounds, work areas, DPI and primary display. Shell surfaces reflow when the topology changes.

⌁

Quick Settings

Appearance and Wi-Fi have native-backed behavior today. Volume, brightness, Bluetooth, airplane and power controls remain staged for direct Windows APIs.

⌨

Activities keyboard entry

Alt+F1 is globally registered with Win32 and toggles Activities. Bare Super is intentionally not claimed until Win-key shortcuts can be preserved safely.

ARCHITECTURE

Web UI where flexibility matters. Rust where Windows matters.

Tauri hosts the WebView2 shell surfaces; Rust owns Win32/DWM calls, display geometry, app discovery, Wi-Fi and global hotkeys.

WHY NOT BETA YET?

Architecture is settling. GNOME fidelity still needs depth.

Current gaps include real workspace integration, live DWM overview thumbnails, safe bare-Super handling, more direct Quick Settings APIs, touchpad gestures, richer motion and broader multi-monitor runtime testing.
