Is FedoraWin ready to showcase?

Yes — as an alpha preview.

The current implementation is coherent enough to show the project direction publicly, provided it is presented honestly as experimental software rather than a finished desktop replacement.

The strongest showcase points are native DWM styling on real application HWNDs, the GNOME-inspired top panel and shell surfaces, real Quick Settings integrations where Windows exposes safe controls, the application grid/search direction, and the project's explicit recovery/safety model.

Working well enough to demonstrate

  • GNOME-inspired top panel with reserved desktop work area.
  • Native DWM styling on real windows while preserving caption buttons, hit-testing, Snap and resize behavior.
  • Activities shell surface with keyboard/click entry points and app/workspace navigation.
  • Paged application grid and Windows application discovery with aliases.
  • Quick Settings UI with direct Windows integration where a safe API is available.
  • Light, dark and system appearance plus libadwaita-inspired accent propagation.
  • Calendar, dash, search and workspace concepts integrated into the shell direction.
  • Recovery tooling and explicit non-destructive boundaries.

Still evolving

  • Live window/workspace presentation needs more GNOME-like fidelity.
  • Quick Settings behavior varies by hardware and by what Windows exposes safely.
  • Multi-monitor behavior needs broader runtime coverage.
  • Spacing, animation and layout still need GNOME 50-level polish in several surfaces.
  • Some Windows-native UI will remain visible by design; the project should integrate it cleanly rather than fake unsupported state.
Alpha means visible rough edges are expected.

Screenshot quality and demo stability are not the same as production reliability.

Release gates

A downloadable public release should wait until these gates are satisfied:

  1. Windows PowerShell 5.1, WPF and native compile/runtime CI is green for the exact release snapshot.
  2. Activities open/close and workspace switching are stable across repeated runs.
  3. Recovery is tested from failure states, not just normal exit.
  4. Quick Settings falls back safely when a hardware/API capability is unavailable.
  5. Packaging is repeatable and does not require destructive Windows changes.

Testing position

The current working snapshot has a passing local regression suite. Windows CI is still treated as the authoritative runtime gate for release decisions.

Most useful alpha feedback

  • Activities crashes, focus problems or keyboard toggle inconsistencies.
  • Window caption/Snap/resize regressions after native styling.
  • Multi-monitor panel/work-area behavior.
  • App discovery misses, especially common aliases such as Terminal.
  • Quick Settings controls that show stale or incorrect Windows state.
  • Light/dark/accent mismatches across shell surfaces.
