Working now

  • Rust + Tauri/WebView2 native shell host.
  • GNOME top panel, Activities surface, app grid, search, calendar and Quick Settings implemented as the Windows shell experience.
  • Windows installed-app discovery and aliases such as Terminal, Files and System Monitor.
  • Real HWND/DWM frame styling using documented attributes.
  • Top work-area reservation through Windows AppBar APIs.
  • Per-monitor bounds, DPI and primary-display discovery, including negative coordinates and ultrawide geometry.
  • Live shell reflow when the display topology changes.
  • Global Alt+F1 Activities hotkey through RegisterHotKey.
  • Direct Wi-Fi radio toggle where the Windows WLAN API accepts it.
  • Light/dark/system shell appearance and accent propagation.
  • Current libadwaita-inspired window/header/card/overview roles, circular shell controls and GNOME motion.
  • Live DWM-backed Activities previews for real top-level application windows.
  • WinEvent-driven Activities refresh for window create/show/hide/title/minimize lifecycle changes.
  • Real Activities window activation and close actions against the underlying HWND.

Partial or scaffolded

  • The workspace strip is visual scaffolding; full Windows virtual-desktop integration is not complete.
  • Bare Super interception is intentionally deferred until normal Win shortcuts can be preserved.
  • Quick Settings volume, brightness, Bluetooth, airplane and power actions are not all directly wired yet.
  • Multi-display geometry exists, but broad physical multi-monitor hardware testing is still required.
  • Touchpad gestures, hot corner, notification ingestion and legacy tray compatibility remain future work.

Immediate engineering priorities

  1. Fold the new WinEvent hooks into a broader ShellRuntime state bus.
  2. Harden DWM thumbnail lifecycle, resize and multi-monitor placement.
  3. Search-provider interface for apps, windows, settings and future providers.
  4. Direct safe Windows APIs for remaining Quick Settings.
  5. Workspace integration and GNOME-like transitions.

Release gates

Current automated gate

Windows CI runs UI contracts, Rust unit tests, cargo check and rustfmt. The Pages workflow separately builds the real executable and requires a fresh runtime screenshot set before deployment.

Still required before beta

Physical multi-monitor testing, mixed DPI, docking/hot-plug, high refresh displays, long-session recovery, touchpad behavior and broader device-control coverage.
